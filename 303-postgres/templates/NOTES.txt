[CNPG Operator 관리]
- -rw  → Primary 접속
- -ro  → Replica 접속
- -r   → 전체 인스턴스 접속
- PostgreSQL Pod / PVC / Service는 CNPG Operator가 생성·관리한다.

[배치]
- 지정된 nodeNames에서만 PostgreSQL 인스턴스를 실행한다.
- podAntiAffinity를 적용하여 한 Node에 여러 인스턴스가 배치되지 않도록 한다.
- 따라서 nodeNames 수와 instances 수가 같아야 한다.
- Node 장애 시 남은 후보가 없으면 새 인스턴스가 Pending 상태가 될 수 있다.
- Primary 위치는 고정하지 않으며 Failover/Switchover에 따라 변경된다.

[주의]
- 설치 순서:
  103-cnpg → 300-data-layer-base → PostgreSQL Chart
- CRD / Operator가 없으면 Cluster 생성에 실패한다.
- 앱 계정 Secret이 없으면 bootstrap이 실패한다.
- helm uninstall 시 Cluster와 PostgreSQL 데이터가 함께 삭제될 수 있으므로 주의한다.
- instances를 늘리면 nodeNames도 함께 확보해야 한다.
