[모니터링 스택 배포 완료]
Release: {{ .Release.Name }}
Chart  : {{ .Chart.Name }}-{{ .Chart.Version }}


[구성]
1. Alloy
   - DaemonSet으로 실행
   - 각 노드마다 1개씩 실행된다.
   - 노드와 컨테이너 메트릭을 제공한다.
   - Prometheus가 메트릭을 가져간다.

2. Prometheus
   - StatefulSet으로 실행
   - Alloy, PostgreSQL, Kafka 등의 메트릭을 수집하고 저장한다.
   - 접속: http://{{ .Values.prometheus.host }}

3. Grafana
   - Deployment로 실행
   - Prometheus의 메트릭을 그래프로 보여준다.
   - 접속: http://{{ .Values.grafana.host }}


[전체 흐름]

노드/컨테이너
      ↓
    Alloy
      ↓
  Prometheus ← PostgreSQL metrics
      ↑
      └────── Kafka JMX
      ↓
   Grafana
      ↓
   브라우저


[클러스터 내부 통신]
Pod에서 다른 서비스에 접근할 때는 Kubernetes Service 주소를 사용한다.

Prometheus:
http://prometheus.{{ .Values.global.namespace }}.svc.cluster.local:{{ .Values.prometheus.port }}

Grafana:
http://grafana.{{ .Values.global.namespace }}.svc.cluster.local:{{ .Values.grafana.port }}

외부 접속용 Host 이름은 Pod 내부 통신에 사용하지 않는다.


[배포 전제]
- 300-data-layer-base가 먼저 설치되어 있어야 한다.
- Namespace, 공용 ConfigMap/Secret, Prometheus가 Kubernetes 리소스를 찾는 데 필요한 권한이 여기서 제공된다.


[설정 변경]
- Alloy와 Prometheus의 수집 설정은 ConfigMap이 관리한다.
- 설정 변경 시 templates/*-config.yaml을 수정하고 helm upgrade 한다.
- kubectl로 ConfigMap을 직접 수정하지 않는다.


[확인]
kubectl -n {{ .Values.global.namespace }} get ds/alloy sts/prometheus deploy/grafana
kubectl -n {{ .Values.global.namespace }} get cm alloy-config prometheus-config
Prometheus의 /targets 페이지에서 모든 수집 대상(Target)이 UP인지 확인한다.


[삭제 시 주의]
- helm uninstall 시 Grafana PVC가 삭제되면 Grafana에서 만든 대시보드가 사라질 수 있다.
- Prometheus 데이터 PVC는 StatefulSet의 볼륨 정책에 따라 남을 수 있으며,
  재설치하면 다시 연결할 수 있다.
