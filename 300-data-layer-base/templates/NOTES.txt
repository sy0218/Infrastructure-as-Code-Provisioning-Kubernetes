[ data-layer 공용 리소스 배포 완료 ]
Release: {{ .Release.Name }}
Chart  : {{ .Chart.Name }}-{{ .Chart.Version }}


[배포 리소스]
1. Namespace
   - data-layer 워크로드 전용 Namespace

2. ConfigMap
   - data-layer-env
     → 전 서비스 공통 환경변수

   (설정 ConfigMap 은 읽는 차트가 소유한다
    → kafka-config / kafka-jmx-exporter 는 301-kafka, alloy-config / prometheus-config 는 302-monitoring
    → 같은 릴리스여야 파드 템플릿에 checksum 을 심을 수 있다)

3. Secret
   - data-layer-secrets
     → DB / MinIO / API 인증 정보

   - {{ .Values.global.postgres.clusterName }}-app-user
     → PostgreSQL 애플리케이션 계정

4. ClusterRoleBinding
   - data-layer Namespace의 default ServiceAccount에
     cluster-admin 권한 부여


[확인]
kubectl get ns {{ .Values.global.namespace }}

kubectl -n {{ .Values.global.namespace }} \
  get cm/data-layer-env secret/data-layer-secrets

kubectl get clusterrolebinding \
  {{ .Values.global.namespace }}-default-admin


[배포 순서]
이 Chart를 먼저 배포한 후
Kafka / MinIO / PostgreSQL / Neo4j 워크로드를 배포한다.

- Kafka       → 301-kafka
- PostgreSQL  → 303-postgres (CNPG)
- MinIO/Neo4j → Ansible로 노드에 구성


[설정 관리]
- 공통 설정 → values.yaml
- ConfigMap / Secret → Helm으로 생성·관리
- 변경 후 → Helm upgrade 또는 ArgoCD Sync
- kubectl로 리소스를 직접 수정하지 않는다.
